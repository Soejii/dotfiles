# Workflow

## 1. Inspect the material

Identify the exact artifact and the requested scope. For an assignment, inspect its instructions, outline, assigned section, group divisions, and supplied sources. For a chapter or paper, inspect the relevant pages or sections. For a transcript, preserve who said what and distinguish instructions from claims.

If the artifact is a local PDF, run:

```bash
/home/suji/.local/bin/pdf-text-cache <file.pdf>
```

Read only the sections needed for the explanation. Use visual inspection for tables or figures whose exact contents matter. Use Hound MCP if a necessary source or external academic context is missing.

## 2. Infer the real question

Determine whether the user needs the whole assignment decoded, a chapter mapped, a paper interpreted, a theory unpacked, or one confusing relationship clarified. Do not begin by asking what is confusing when a useful first explanation can reveal it. Ask one concise question only when different interpretations would materially change the answer.

## 3. Build the mental model

Privately establish:

1. The one-sentence gist.
2. The prerequisite ideas.
3. The central problem, mechanism, or argument.
4. How the major parts depend on or contrast with one another.
5. A concrete example.
6. The scope, limitations, and unresolved claims.
7. How the material connects to the user's assignment or purpose.

## 4. Explain

Lead with what the material is really about. Continue in dependency order, using the minimum structure needed for clarity. Separate central ideas from supporting detail. Give source locations when the explanation depends on a supplied document.

## 5. Re-pitch when needed

If the explanation does not land, diagnose the likely failure: an undefined term, missing prerequisite, excessive abstraction, excessive compression, or a confused relationship. Switch routes by using a causal chain, worked example, comparison, smaller scale, larger overview, or outcome-first explanation.

## 6. Check understanding only when useful

Use one small, targeted question that tests the relationship most likely to be misunderstood. Do not turn the interaction into an unsolicited quiz.

## 7. Preserve the boundary

Do not silently turn the explanation into assignment prose or edit files. If the user asks to transform the understanding into academic writing, use `$academic-writer` under that skill's rules.
